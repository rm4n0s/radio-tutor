## 1.1 Timeline model and evaluation
Date: 2026-10-30.

Built:
- `internal/core/problem`: `Problem{Path, Message string; Warning bool}` (JSON tags `path`, `message`, `warning,omitempty`, for `validate --json`), `String()` (`path: message`, `warning: ` prefix for warnings), `Errorf`/`Warnf` constructors, `List` (`[]Problem` with `Add`, `Errorf`, `Warnf`, `HasErrors`; zero value ready, assignable to `[]Problem`), `HasErrors`, `Errors`, `Warnings`, path helpers `Join` and `Index`, and `Prefixed(prefix, ps)` / `InFile(file, ps)` which return prefixed copies. Convention for later validators: a validator builds paths relative to what it validates (`tracks[2].keys[5].opacity`) and returns `[]problem.Problem`; the caller that knows the file applies `InFile`, which writes `lessons/l1/lesson.json#tracks[2].keys[5].opacity`, so the printed form is `file#field.path: message`. A cassette is valid when `HasErrors` is false.
- `internal/core/timeline`: `Track`, `Key` (optional properties are `*float64`; `Float(v)` helper), `Caption`, `Ease` and `RevealFrom` string types with constants, `Valid()`, `RevealFrom.Or()`; `ActorState` and `DefaultState()`; `Ease.Apply(u)` (linear, cubic in/out/in-out, step); `Evaluator` (`NewEvaluator(tracks)`, `Len`, `Actor(i)`, `Evaluate(t, dst) []ActorState`) and the convenience `Evaluate(tracks, t) []ActorState` (track order); `CaptionAt(captions, t)`; `Validate(tracks, captions, length) []problem.Problem`.
- Evaluation design: the player builds an `Evaluator` once per lesson; it splits every track's keys per property (with the key's ease), so a frame does a binary search per property and writes into a slice the caller owns and reuses (zero allocations, asserted with `testing.AllocsPerRun`). Per property: before the first key that sets it the first value, between two keys the later key's ease, after the last the last value, unset properties keep their defaults (opacity 1, x 0, y 0, scale 1, rotate 0, reveal 1). The Evaluator is immutable, so it is safe to share. The player applies the transforms in the spec's order (scale and rotate around `origin`, then move).
- `CaptionAt` shows a caption for `start <= t < end` (end exclusive, so two touching captions never both match); captions must be ordered (binary search).
- `Validate` rules: actor present and unique per track; `origin` two finite numbers and present when a key sets scale or rotate; `reveal_box` four finite numbers, positive width and height, present when a key sets reveal; `reveal_from` valid; 1 to 1000 keys with strictly increasing `t` in `[0, length+0.05]`; opacity and reveal in 0 to 1; scale in (0, 20]; x, y, rotate finite; ease valid; at least one caption; text 1 to 200 characters (runes), not blank, at most two lines; `start >= 0`, `start < end`, `end <= length+0.05`; ordered and not overlapping (touching is fine). Not here (they need other packages): the actor exists in the scene, `reveal_box` inside the view box.

Tests:
- `problem`: `String`, `Join`/`Index`, `List` and the filters, `Prefixed`/`InFile` (input unchanged), JSON.
- `timeline`: easing values and monotonicity; table-driven evaluation (before first key, at the first key, linear and each ease between keys, the later key's ease only, step on both sides of the key, after the last key, properties set by different keys, zero versus absent, several tracks, all six properties); zero allocations and snapshot behavior of the Evaluator; 1000 keys; unordered keys do not panic; `CaptionAt` at every boundary; one test per validation rule with its path and message, all problems collected at once, the 0.05 s tolerance.

## 1.4 Ogg Vorbis decoding
Date: 2026-10-30.

Built:
- Dependency `github.com/jfreymuth/oggvorbis@v1.0.5` (with `github.com/jfreymuth/vorbis@v1.0.2`); both are pure Go (no `import "C"`, checked in the module cache).
- `internal/core/audio`: `Clip{SampleRate, Channels int; Samples []float32}` (interleaved, -1..1) with `Frames()`, `Seconds()`, `Duration()`; `Info{SampleRate, Channels int; Frames, Bytes int64}` with `Seconds()`, `Duration()`; `Decode(ctx, r) (*Clip, error)`; `DecodeLimit(ctx, r, maxSeconds)` (Decode that fails with `AudioTooLong` as soon as the audio is longer than the limit, so an unprobed file cannot fill memory); `Probe(ctx, r) (Info, error)`; `CheckNarration(info, maxSeconds) []problem.Problem` with the constants `MaxNarrationSeconds` (600), `MaxPromptSeconds` (60) and `MaxBytes` (20 MiB). Problems have an empty path: the caller applies `problem.InFile` (for example `lessons/l1/narration.ogg`), and passes `MaxPromptSeconds` for `prompt.ogg`.
- Design: one internal `stream` function decodes block by block (4096 frames) and hands each block to a sink; `Decode` appends the blocks, `Probe` drops them (constant memory). The length is counted while decoding, not taken from the container: the library's `Length()` needs a seekable reader and trusts the last page's granule position, while the count is what the player will really play (and works for any `io.Reader`; the reader is hidden behind a struct so the library never seeks). `Probe` also reads the bytes after the last page so `Info.Bytes` is the file size (CheckNarration's 20 MiB rule). The context is checked before every block. The library panics on some hostile input (an Ogg page with no segments, found by hand); `stream` recovers and returns `AudioDecoderPanic`.
- Error tags: `AudioHeaderInvalid` (not Ogg Vorbis, bad or truncated headers), `AudioFormatInvalid` (no sample rate or channels), `AudioDataCorrupt` (bad checksum, truncated data; the original error is kept for `errors.Is`), `AudioDecoderPanic`, `AudioTooLong`, `AudioCanceled` (keeps the context error: `errors.Is(err, context.Canceled)`), `AudioReadFailed` (reading after the last page).
- `CheckNarration` rules: rate 22050/44100/48000, 1 or 2 channels, not empty, at most `maxSeconds`, at most 20 MiB when `Bytes` is known. Every problem is reported.
- Test data in `internal/core/audio/testdata/` (4 to 8 KB each): 1 s tones mono 44100, stereo 48000, mono 22050, mono 16000 (unsupported), a corrupted copy and a truncated copy of the first; `README.md` has the exact ffmpeg commands.

Tests: durations, channels, rates and exact frame counts of every file through `Probe` and `Decode` (and that the two agree); sample content (440 Hz zero crossings, peak in range); a one-byte-at-a-time and half-reader (non-seekable); trailing bytes counted; every error tag with its route (empty input, not Ogg, truncated headers, corrupt page, truncated data, page with no segments, zero rate, zero channels); `DecodeLimit`; cancellation (already cancelled, in the middle, deadline, while reading the trailing bytes); `CheckNarration` for every rule and for the probed files with `InFile`.

Deviations from the spec: none. `DecodeLimit` and the `Bytes` field of `Info` are additions to the plan.

Manual checks: none (no sound is played in this step).

Later:
- Step 5.1 adds the player and the sinks to this package; they take a `*Clip`.
- A truncated file whose cut falls exactly on a page boundary decodes without error (the library cannot tell it from a finished stream without the end-of-stream flag); it is just shorter, and the narration length is the lesson length, so nothing else breaks.
## 2.1 Profiles
Date: 2026-10-30.

Built:
- `internal/core/profile`: `Store` over `profiles.json` (`{"format": 1, "profiles": [{username, display_name, role, password_hash, created_at}]}`), `Open(ctx, path, opts...)` (missing file = empty store; `format` other than 1 fails with `ProfilesFormatUnsupported`; an invalid or repeated username, an invalid role or display name, or a damaged hash fail at open; invalid JSON is the storage tag `JSONInvalid`, and the file is not moved: the app start decides on `storage.QuarantineBroken`, `reset-password` just fails). Options `WithClock(func() time.Time)` and `WithIterations(n)`. Methods: `Create(ctx, username, displayName, role, password) (Profile, error)`, `List`, `Get`, `Rename`, `SetPassword`, `Delete` (the last admin is refused with `LastAdmin`), `Login(username, password) (Profile, error)`, `NeedsFirstAdmin()`. `Profile` has no hash. `Role` (`RoleAdmin`, `RoleStudent`, `Valid`, `MinPasswordLength`: 8 and 4). Usernames are lower-cased on every entry point and must match `^[a-z0-9_]{2,32}$`; display names are trimmed and 1 to 40 characters; password lengths count characters (runes).
- Concurrency and persistence: a mutex guards the store; every change builds the new record list, writes it with `storage.WriteJSONAtomic`, and only then makes it current, so a failed write changes nothing in memory. Hashing (about 0.3 s) is done outside the mutex.
- Hash (`password.go`): `pbkdf2-sha256$<iterations>$<salt b64>$<key b64>` (standard base64 with padding), 16-byte salt from `crypto/rand`, 32-byte key from `crypto/pbkdf2` with SHA-256, 600,000 iterations by default (`DefaultIterations`). Verification takes the iteration count, salt and key length from the stored hash and compares with `crypto/subtle`. A stored hash is range-checked (iterations 1..10,000,000, salt 8..64 bytes, key 1..64 bytes) before use.
- Login throttle: in memory, per lower-cased username (known or not), after 5 failed logins that username is refused with `LoginThrottled` (metadata `retry_after`) for 30 seconds by the injectable clock, without looking at the password; the wait ends by itself, a success or deleting the profile clears the count, a new wait needs 5 new failures. A wrong password and an unknown username are both `LoginFailed` (the unknown one still pays one hash derivation, so timing does not tell them apart).
- `cmd/radio-tutor reset-password <username>` (`resetpassword.go`): resolves the folders, takes `storage.Lock` (`AlreadyRunning` prints "Radio Tutor is already running", exit 2), opens the store, checks the user exists (else `no user named "x"`, exit 1), reads the password twice and calls `SetPassword` (the role's minimum length is enforced there and the message names it). When stdin is a terminal (`terminalEcho`: a `*os.File` that answers `TCGETS`), the prompts go to stderr and the echo is turned off with `unix.IoctlGetTermios/IoctlSetTermios` (`TCGETS`/`TCSETS`, clearing `ECHO` only) and restored by a `defer` and when the context is cancelled (SIGINT/SIGTERM come through `signal.NotifyContext`; the blocked read is abandoned). Otherwise one line per password, `\n` or `\r\n`, a last line without a newline is accepted, no prompts. The terminal sits behind the small `echoControl` interface and `termiosOps`. Usage errors exit 2.
- `run` now takes the stdin `io.Reader` after `args` (`main` passes `os.Stdin`).
- `golang.org/x/sys` became a direct dependency (already allowed; it was indirect through Glutter).

Tests:
- `profile`: hash format (parts, sizes, key equals PBKDF2 of the password, salts differ, default 600,000), verification using the stored iteration count, every damaged-hash case with its tag, random-source and derivation failures; every `Create` rule (username pattern and length limits, case, display name limits and trimming, role, password minimums per role counted in characters, duplicate case-insensitively); `List`/`Get`/`NeedsFirstAdmin`/creation times; `Rename`, `SetPassword`, `Delete` with the last-admin rule and persistence; login (case, wrong, unknown, empty); the throttle (4 failures, the 5th starts the wait, right password refused during it, 29 s still waiting, other users unaffected, expiry at 30 s, success resets, 5 more failures for a new wait, unknown names, in memory only, delete clears it); `Open` on every bad file; the file content and mode; a failed write (read-only folder) leaves memory unchanged for all four mutations; 8 goroutines under `-race`.

## 1.2 Cassette documents
Date: 2026-10-30.

Built:
- `internal/core/cassette`: `Load(ctx, fsys fs.FS) (*Cassette, []problem.Problem, error)` reads `cassette.json`, every `lessons/<id>/lesson.json` and `exercises/<id>/exercise.json` and collects every problem (paths `cassette.json#items[2].id`, `lessons/l1/lesson.json#captions[2].end`; a missing file or folder has the file or folder as its path). Types: `Manifest`, `Item`/`ItemType`, `Lesson` (`ID`, title, summary, `[]timeline.Track`, `[]timeline.Caption`), `Exercise` (`ID`, all fields of CASSETTE-FORMAT §7.2, `Label` with the default applied, `MaxAttempts` with the default 3), `Cassette` (`Manifest`, `Lessons` and `Exercises` by id), `Worksheet{Index, Start, ExerciseIDs}`, `Cassette.Worksheets()` and `WorksheetOf(exerciseID)` (computed from the items: maximal runs of exercise items), `Version` (`ParseVersion`, `Compare`, `Less`, `String`, JSON as a string).
- The returned `*Cassette` is nil only when `cassette.json` is missing, is not UTF-8 JSON of the right shape, or has a newer format. Otherwise it holds the manifest and every lesson and exercise whose file was readable and had the right shape, even when a field rule failed; use it only when the problems have no errors (the archive step can still run its other checks on a cassette with errors).
- Reading: a document is read at most 1 MiB, rejected with a BOM or invalid UTF-8, parsed by `encoding/json` tokens into a small tree (`node`) that remembers which fields exist and reports duplicate fields and the line of a syntax error, checked against a declarative schema (unknown fields, missing required fields, wrong JSON types, whole numbers, numbers out of range, the version string), and only then decoded (`DisallowUnknownFields`) into the Go types. This is how a missing `t`, `start`, `end` or `format` is told from 0 without changing the timeline types. A document with a structure problem reports only those problems (its field rules are skipped until it is fixed). `format` greater than 1 reports "This cassette needs a newer Radio Tutor" and nothing else for that file.
- Field rules: everything in CASSETTE-FORMAT §3, §5.3, §7.2 and the ids of §2; lengths count runes; blank text is "must not be empty"; BCP 47 language through `golang.org/x/text/language` (now a direct dependency in `go.mod`; it was already an indirect one through Glutter); a lesson is checked with `timeline.Validate(..., timeline.LengthUnknown)`. Cross-document rules: item ids valid and unique across lessons and exercises; every listed folder exists with its JSON; a folder under `lessons/` or `exercises/` that no item of that type lists is an error; the first item being an exercise is a warning (`items[0]`); labels unique after the defaults (the default is the exercise's 1-based position among all exercise items, also when an earlier exercise's file is broken). Files that are not folders under `lessons/` and `exercises/`, and every file other than the JSON ones, are left to the archive step.

## 1.3 Scene layers

Built:

- `SilentSink` (wall clock), `FakeSink` (position follows the injected clock; simulates the device by pulling the samples "played" from the `Source`; records `Calls()` and `Played()`; `FailStartWith(err)`), `PulseSink` (`NewPulseSink(ctx, PulseOptions)`), `OpenDefaultSink(ctx) (sink Sink, reason error)`.

Behavior:
- Position: 0 when stopped, held when paused, advancing while playing, `Duration()` after the end. It never decreases between a Play and the next Stop (the tracker holds the position when a server measurement is behind it). `Play` after the end restarts from 0 (SPEC §8); `Stop` after the end goes to 0.
- Goroutines: `Position`, `State`, `Duration` take a short mutex and never wait for the audio server (the sinks' `Position` does not either), so the UI can call `Position()` once per frame. `Play`, `Pause`, `Stop`, `Load` may wait for a server round trip (about 1 ms; 12 ms for a resume; bounded by timeouts of 2 to 3 s) and are meant for event handlers. The end is detected by a `Clock` timer, which fires on its own goroutine (the runtime's timer goroutine, or the caller of `Advance`); it sets `StateEnded`, stops the sink and signals `Ended()`. `Ended()` is a channel with room for one value and a non-blocking send (ends nobody read are merged); the UI should select on it from a goroutine of its own and hand the news to the UI thread with `SetState`/`Post`, or just compare `State()` each frame. `Position()` never changes state.
- End detection: the timer is armed for `duration - sink.Position()`; if the sink is behind when it fires (device latency, a late measurement), it looks again for the rest. So the lesson ends when the audio has been played, not when it was written.
- `PulseSink`: the library is pull-based (a reader callback fills the server's buffer), so the plan's "write" is the `Source` that the sink pulls from (SPEC §8.1 reworded). After the source ends the callback returns silence, so the stream keeps running until the Player stops it. The library has no played-position call: every 100 ms the sink sends `GetPlaybackLatency` and computes `played = read index / (rate * bytes per frame) - latency` (the same as the written samples minus the buffered ones minus the device latency), timestamped at the middle of the request, and extrapolates with the clock in between (SPEC §8.2 reworded). A first measurement is taken before `Start` returns. If the server stops answering the clock goes on, so a lesson still finishes. The stream is created with 100 ms latency, 32-bit float samples, mono or stereo at the clip's rate (the server resamples), named "Radio Tutor".
- **Pause closes the stream and Resume opens a new one** at the held position (`Source.SeekFrame`), instead of corking. Found against PipeWire's PulseAudio server: after `Resume` (uncork) the server sends a "started" event, which the library delivers on an unbuffered channel that only `Start` reads, so the library's connection loop blocks and every later request times out after 2 s (a stop took 4 s, the clip ended 4 s late). A new stream costs about 12 ms and the position is right to about 20 ms. `Resume` can therefore fail (`PulseStreamFailed`...), in which case `Player.Play` returns the error and the Player stays paused.
- `OpenDefaultSink`: `PULSE_SERVER` if set and not empty, else `unix:$XDG_RUNTIME_DIR/pulse/native`; with neither it returns `PulseNoServer`. The library reads the cookie from `$PULSE_COOKIE` or `~/.config/pulse/cookie`, as every PulseAudio client does. It never returns a nil sink: on failure the `SilentSink` and the reason (`*errors.Error`, route `OpenDefaultSink->NewPulseSink->dialPulse.<Tag>`) so the UI can show "No sound device found" once and log the reason. The library's connect cannot be cancelled, so a cancelled `ctx` or the 5 s timeout returns at once and a goroutine closes the connection if it ever completes.
- Error tags: `PlayerClipInvalid`, `PlayerClosed`, `PlayerNoClip`, `PlayerCanceled`, `SilentStartCanceled`, `FakeStartCanceled`, `PulseNoServer`, `PulseConnectFailed`, `PulseConnectCanceled`, `PulseConnectTimeout`, `PulseClosed`, `PulseFormatUnsupported`, `PulseStreamFailed`, `PulseStartCanceled`, `PulseStartTimeout`.

Written to a temporary file next to `out`, read back with `OpenZip` (a very compressible file can break the ratio rule: then the problems are returned and nothing is written), renamed to `out`; an existing `out` is an error unless `force`. Folder problems (extra files, links) are returned and nothing is written.
  - `Store` (`NewStore(paths, render)`): `List(ctx)` (sorted, broken entries included with their problems; temporary folders and non-id names are skipped), `Get(ctx, id) (fs.FS, cassette.Manifest, error)`, `Import(ctx, path, confirmUpgrade) (ImportResult, error)`, `Remove(ctx, id)` and `Recover(ctx)`. `ImportResult{Status, ID, Version, Previous, Problems}` with the statuses `ImportInvalid` (the problems; nothing written), `ImportInstalled`, `ImportUpgraded`, `ImportAlreadyInstalled`, `ImportNewerInstalled`, `ImportDeclined`. Import reads and validates without the lock, asks `confirmUpgrade(old, new)` without the lock (a nil function declines), extracts into `cassettes/<id>_tmp-<random>/` (modes 0700/0600, every file synced), checks that the extracted manifest is the validated one, and under the mutex compares the state again and swaps: rename the old folder to `<id>_old-<random>`, rename the new one in (undo on failure), delete the old one (a failure is a warning in `Problems`; `Recover` deletes it later). If another import got there first the answer is the final status (`ImportAlreadyInstalled`/`ImportNewerInstalled`), or the error `StoreChangedDuringImport` when an upgrade nobody confirmed would be needed. Cancelling `ctx` deletes the temporary folder. A broken installed copy is replaced without asking. `Remove` renames the folder away and deletes it, so the cassette disappears at once. `Recover` (at start, before imports) deletes `_tmp-` folders, renames an `_old-` folder back when the cassette's own folder is missing and deletes it otherwise.

Built:
- `internal/gui/player` (new package; imports `app` and `student`; `desktop.Screens()` wires `student.Screens{Lesson: player.Builder()}`):
  - `Lesson` / `NewLesson(req)` / `Builder()`: the screen. A stateful widget; one goroutine per screen (`State.Go`) owns the `audio.Player`: it loads the lesson (`loadLesson`: reads `scene.svg` and `scene.Split`s it, decodes `narration.ogg` with `audio.DecodeLimit`, opens the sink through `Env.SinkFactory` (6.5's factory; the player's end timer runs on `Env.AudioClock`), loads the clip), reads the student's `skip_lessons` setting, hands the result to the UI with `SetState`, then serves commands (play, pause, stop, sent by the UI on a channel) and the player's `Ended()` channel until its context ends (the screen was left), when it closes the player and the sink. The UI thread never calls the sink: starting and stopping a Pulse stream waits for the server. Tapping while a command is running queues it (8 deep, a full queue drops).
  - Stage (`stage.go`): `newStage` makes one `svg.SvgPicture` per layer once (from the layer bytes); every frame only the wrappers of the actors are rebuilt, around the same picture widgets, so the pictures are not parsed or rebuilt. The stage is a `LayoutBuilder` + `SizedBox` of the view box's aspect ratio (contain, centered, letterboxed in the scaffold's background) with a `Stack` of `StackFitExpand`. An actor that has a track is `Opacity(Transform(ClipRect(picture)))`: `actorMatrix` is T(x,y) T(origin) R S T(-origin) in stage pixels (`k` = pixels per view box unit, view box origin subtracted from the origin point); the reveal clip is inside the transform, so it moves and turns with the actor (the reveal box is in the actor's own coordinates), and is `revealRect` of the box from the track's side, empty at reveal 0; at reveal 1 the clipper returns the whole box, so strokes at the edge of the box are never cut. Static layers, and actors without a track, are drawn as they are. One `timeline.Evaluator` and one reused `[]ActorState`.
  - Frame loop: a `Ticker` (`SingleTickerProvider`) reads `Player.Position()` once per frame and `SetState`s it. The ticker starts when a command leaves the player playing and stops when the player is paused, stopped or ended, so a paused lesson costs no CPU (tested through the scheduler's transient callback count).
